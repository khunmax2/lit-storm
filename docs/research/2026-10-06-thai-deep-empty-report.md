# Deep Research ภาษาไทยจบด้วย empty_report (2026-10-06)

**อาการ:** Run แบบ Deep Research ระดับเร็ว หัวข้อ "รถไฟความเร็วสูงไทย-จีน" ภาษาไทย ค้นด้วย SearXNG (`http://searxng:8080/search`, engines null) บน stack `litstorm` ในเครื่อง ล้มเหลวด้วยเหตุผล `empty_report`
- Engine สร้างคำค้น 2 ข้อ
  - "ความคืบหน้าล่าสุด โครงการรถไฟความเร็วสูงไทย-จีน 2569"
  - "ปัญหาและอุปสรรค โครงการรถไฟความเร็วสูง กรุงเทพ-หนองคาย"
- ทั้งสองข้อได้ผลเป็นคำถามจาก zhihu.com และ zhidao.baidu.com กับหน้าพจนานุกรมของคำว่า "ความ" (dict.longdo.com, wiktionary, translate.google.co.th) และจบที่ `no_evidence`
- หัวข้อเดียวกันเป็นภาษาอังกฤษสำเร็จ และ STORM ภาษาไทย ("ประเพณีสงกรานต์") ได้แหล่งอ้างอิง 10 รายการ

Run ที่ล้มเหลวไม่อยู่ในฐานข้อมูลแล้ว (น่าจะถูกลบไปแล้ว) ผลข้างล่างจึงได้จากการถาม SearXNG ใน stack ตรงๆ ด้วยคำค้นชุดเดิม

## สรุป

- **ไม่ใช่เรื่องภาษาไทย การเข้ารหัส หรือปี พ.ศ.** ปัญหาอยู่ที่ engine ค้นเว็บที่อยู่หลัง SearXNG ของเราตอนนี้
  - Google, Brave, DuckDuckGo และ Google CSE ถูกพักทั้งหมด
  - Bing ตอบผลของคำค้นอื่นมาทั้งหน้า เช่น Windows, Roblox, LINE หรือ Q&A ภาษาจีน และเป็นแบบนี้กับคำค้นภาษาอังกฤษด้วย
  - Yahoo บางครั้งค้นแค่คำแรกของคำค้น เช่น "ความ", "ประวัติ" หรือ "Thailand"
- **Deep Research ไม่ได้ผ่าน SearchBridge** ถ้า Run ใช้ SearXNG แหล่งเดียว CLI ของ Deep (Node) เรียก SearXNG เอง แล้วเก็บ 5 ผลแรกไว้โดยไม่ได้ดูว่าตรงเรื่องหรือไม่
  - ระดับเร็วมีคำค้นแค่ 2 ข้อ เมื่อผลทั้ง 5 ของทั้งสองข้อมาจากคำค้นอื่น ขั้นตรวจหลักฐานของ Deep ก็ไม่พบหลักฐาน รายงานจึงว่าง
- **STORM รอดเพราะโครงสร้าง ไม่ได้ค้นต่างกัน** STORM ค้นหลายสิบครั้งต่อ Run และไม่มีขั้นตรวจหลักฐานรายคำค้น ผลขยะจึงแค่ไม่ถูกอ้าง
- **ที่แก้แล้ว:**
  - retriever SearXNG ของ STORM ตัดผลที่แทบไม่มีถ้อยคำร่วมกับคำค้นทิ้ง แล้วเติม `k` จากผลที่เหลือ
  - Deep Research ค้น SearXNG ผ่าน SearchBridge ซึ่งใช้ retriever ตัวนั้น
- **ที่ยังไม่หาย:** ผลที่ตรงคำค้นแค่บางส่วน เช่น Yahoo ค้นแค่คำแรก ยังผ่านตัวกรองได้ และบางคำค้นไม่มีผลที่ตรงเรื่องจาก engine ไหนเลย ต้องแก้ที่แหล่งค้น (ดูท้ายเอกสาร)

## Deep ส่งอะไรให้ SearXNG

- Run ที่มี SearXNG แหล่งเดียวไม่ได้ผ่าน SearchBridge
  - `bridged()` คืนค่า false เพราะ CLI รู้จัก SearXNG อยู่แล้ว
  - CLI (`deep-research-web-ui/lib/core/web-search.ts`, `searchWithSearxng`) จึงส่ง `GET /search?q=<คำค้น>&format=json&language=th` เอง
  - ไม่ส่ง `engines` เพราะค่าเป็น null
- **การเข้ารหัส:** คำค้นถูกเข้ารหัสแบบ UTF-8 percent-encoding และ SearXNG ส่ง `query` กลับมาตรงกับที่ส่งไปทุกคำค้น
- **`language`:** ส่ง `none`, `th` หรือ `auto` แล้วได้จำนวนผลและจำนวนผลที่ตรงเรื่องเท่ากันใน 19 จาก 24 ชุดของสองรอบแรก อีก 5 ชุดต่างกันไปคนละทาง (`th` ดีกว่าครั้งหนึ่ง แย่กว่าสามครั้ง และ `none` ได้ 0 ผลครั้งหนึ่ง) และไม่เกิดซ้ำในอีกรอบ จึงเป็นความไม่นิ่งของ engine ไม่ใช่ผลของ language
  - STORM ไม่ได้ส่ง `language` เลย
- **ปี "2569":** ไม่ได้เป็นต้นเหตุ ในการวัดรอบแรก คำค้นที่มี 2569 ได้ผลจาก Bing ตรงเรื่อง 10/10 ส่วนคำค้นเดียวกันที่ตัดปีออกได้ 0/10
- **การเลือกผล:** CLI เก็บผลที่มีเนื้อหา 5 ตัวแรกตามลำดับของ SearXNG ซึ่งจัดผลของแต่ละ engine สลับกัน
  - Bing ให้ผลมา 10 ตัว Yahoo 7 ตัว ผลจากคำค้นอื่นจึงได้ที่ใน 5 อันดับแรกได้ 2–3 ที่ แม้ Yahoo จะตอบถูก

## engine แต่ละตัวทำอะไร

วัดจากใน worker ด้วยคำค้นของ Run (สคริปต์ `server/tests/searxng_relevance.py`) "ตรงเรื่อง" คือมีคำหลักของหัวข้อ เช่น "รถไฟ" หรือ "ไฮสปีด"

| คำค้น | Bing | Yahoo | รวมทุก engine (5 อันดับแรก) |
|---|---|---|---|
| ความคืบหน้าล่าสุด … ไทย-จีน 2569 | 10/10 ตรง (ทั้ง 2 รอบ) | 7/7 ตรง | 5/5 |
| ปัญหาและอุปสรรค … กรุงเทพ-หนองคาย | 0/10: support.google.com, geeksforgeeks, windows-10-forum, ปฏิทิน myhora | 7/7 ตรง, รอบหลังได้ 0 ผล | 2/5 |
| ความคืบหน้าล่าสุด … ไทย-จีน (ไม่มีปี) | 0/10: Roblox, reddit, ผลบอล | 7/7 ตรง, 1 ใน 6 ครั้งได้หน้าพจนานุกรม "ความ" 10 ผล | 0–5/5 |
| ประเพณีสงกรานต์ | 0/10: zhidao.baidu.com, zhihu.com | 7/7 ตรง หรือ 0 ผล | 2–5/5 |
| CRISPR off-target effects | 0/10: หน้า Google Account | 0 ผล | 0/5 |
| Thailand China high-speed railway progress 2026 | 0/10: หน้าท่องเที่ยวไทย | หน้าท่องเที่ยวไทย (ค้นแค่ "Thailand") | 0–2/5 |

- ในทุกการวัด ไม่มี engine ไหนตอบเรื่องที่ตรงคำค้นได้สม่ำเสมอ
- เมื่อถาม Yahoo ตรงๆ ด้วย User-Agent ของเบราว์เซอร์ คำค้น CRISPR ได้หน้าที่ไม่มีผลค้นหา อาการเข้ากับการกันบอตของ Yahoo และ Bing ต่อ IP นี้ **[อนุมาน]**
- engine ที่ปิดไว้ได้ผลดังนี้
  - Bing News ได้ผลตรงเรื่อง 9/9 และ 7/7 ในรอบแรก แต่รอบถัดไปได้ 0 ผลใน 4 จาก 6 คำค้น
  - Qwant ขอ CAPTCHA
  - Google News ถูกพักด้วย access denied
  - จึงไม่มีตัวไหนเปิดแทนได้ทันที

## ทำไม STORM ภาษาไทยได้ แต่ Deep ไม่ได้

| | STORM | Deep Research (ระดับเร็ว) |
|---|---|---|
| คำค้นต่อ Run | หลายสิบ (Run ภาษาไทยใน DB ค้น 11–70 ครั้ง) | 2 คำค้น แต่ละคำค้นเขียนใหม่ได้อีก 1 ครั้ง |
| ผลที่เก็บต่อคำค้น | `k` ผลแรกที่ผ่าน `is_valid_source` | 5 ผลแรกที่มีเนื้อหา |
| ผลขยะ | ไม่ถูกอ้างในรายงาน แต่ Run ยังไปต่อ | ขั้นตรวจหลักฐาน (`assessSearchLearnings`) ไม่ผ่าน ถ้าทุก node เป็น `no_evidence` ผลคือ `empty_report` |
| `language` | ไม่ส่ง | `th` (ไม่มีผลต่างที่วัดได้) |
| ผ่าน SearchBridge | ไม่เกี่ยว (ใช้ retriever ตรง) | ไม่ผ่าน ถ้ามี SearXNG แหล่งเดียว |

ภาษาอังกฤษสำเร็จได้เพราะ engine ตอบดีในตอนนั้น หรือเพราะคำค้นสองข้อนั้นโชคดี ผลวันนี้แสดงว่าคำค้นภาษาอังกฤษก็ได้ผลขยะจาก Bing เหมือนกัน

[2026-10-05-searxng-vs-ldr-academic.md](../benchmarks/2026-10-05-searxng-vs-ldr-academic.md) วัดว่า "คำค้นไทยได้หน้าไทยครบ 5/5" ตัววัดนั้นมองไม่เห็นปัญหานี้ด้วยสองเหตุ
- **`top5_thai` นับผลที่มีอักษรไทย ไม่ได้นับผลที่ตรงเรื่อง** หน้าพจนานุกรม "ความ" หรือปฏิทิน myhora ก็นับเป็นหน้าไทย
- **ตอนนั้น Google CSE ยังตอบ** (เอกสารเขียนว่าผลค้นเว็บจริงมาจาก Google CSE, Bing และ Yahoo) วันนี้ Google CSE ถูกพักด้วย "too many requests" เหลือแค่ Bing กับ Yahoo

## สิ่งที่แก้

1. **`knowledge_storm/rm.py`, `on_topic` และ `SearXNG.forward`:** ผลที่มีชิ้นสามตัวอักษรร่วมกับคำค้นน้อยกว่าหนึ่งในสิบจะถูกตัดทิ้ง โดยเกณฑ์สูงสุดไม่เกิน 4 ชิ้น
   - ชิ้นสามตัวอักษรนับจากตัวอักษรและตัวเลขที่ตัดช่องว่างกับเครื่องหมายออกแล้ว ไม่ต้องตัดคำภาษาไทย
   - retriever เติม `k` จากผลที่เหลือ นับจำนวนที่ตัดไว้ใน `off_topic` และเขียน log ทุกครั้งที่ตัด
   - เกณฑ์มาจากผลจริงของวันนั้น 175 ผล (ผลที่ตรงเรื่องมีชิ้นร่วม 5–30 ชิ้น และ 0.13–0.82 ของคำค้น) ตัดผลขยะที่มาจาก Bing ล้วนได้ 69 จาก 79 ผล และไม่ได้ตัดผลที่ตรงเรื่องเลย
   - การวัดซ้ำด้วย `searxng_relevance.py` (24 แบบ) ตัดไป 99 ผล ไม่มีผลที่ตรงเรื่องเลย
   - เกณฑ์มีสองส่วนเพราะใช้อัตราส่วนอย่างเดียวจะทำให้คำค้นยาวต้องการชิ้นร่วมมากเกินไป
   - คำค้นสั้นกว่า 3 ตัวอักษรไม่ถูกกรอง
2. **`server/src/litstorm/engines/deep/engine.py`:** `SEARCH` เหลือแค่ Tavily ทำให้ SearXNG ผ่าน SearchBridge
   - CLI ได้ผลจาก retriever ข้อ 1 (bridge ขอ 10 ผล CLI เก็บ 5)
   - ได้ cache ผลค้นของ Run ไปด้วย
   - ไม่ส่ง `language` อีกต่อไป (วัดแล้วไม่ต่าง)

STORM และ Co-STORM ได้ตัวกรองนี้ด้วย เพราะใช้ retriever ตัวเดียวกัน

**ผลข้างเคียงที่ยอมรับ:**
- ผลที่ถูกเรื่องแต่ใช้ถ้อยคำคนละแบบจะถูกตัดได้ เช่น คำค้นไทยที่ได้ผลเป็นภาษาอังกฤษล้วน
- ผลใน cache (`search_cache`, 24 ชั่วโมง) ที่เก็บก่อนแก้ไม่ได้ผ่านตัวกรอง และจะหมดอายุเองภายในหนึ่งวัน

## ที่ยังต้องทำ

- **แหล่งค้นเว็บที่ตอบได้จริงคือต้นเหตุที่เหลือ** ตอนนี้ engine ค้นเว็บทุกตัวของ SearXNG ถูกพัก หรือตอบผลขยะกับ IP นี้ ทางเลือกที่ต้องตัดสินใจ:
  - ตั้ง Tavily เป็นแหล่งของ Run
  - ใส่ Google CSE key ที่มีโควตา
  - ใช้ Brave Search API แบบมี key เป็น Search Provider ของตัวเอง
  - แบบไม่มี key ยังไม่มีตัวเลือกที่วัดแล้วว่าใช้ได้
- **Agent Research** ยังใช้ SearXNG client ของตัวเอง ไม่ได้ผ่านตัวกรองนี้ ถ้าจะให้เหมือน Deep ให้เอา `"searxng"` ออกจาก `SEARCH` ใน `engines/agent/engine.py`
  - โมเดลของ Agent เลือกผลเองอยู่แล้ว จึงเจ็บน้อยกว่า Deep
- **ผลที่ตรงแค่บางส่วน** (Yahoo ค้นแค่คำแรก) ตัวกรองแบบถ้อยคำแยกไม่ได้
  - ผลที่ตรงเรื่องน้อยที่สุดของวันนั้น (mgronline 0.13) กับหน้าพจนานุกรม "ความ" (0.06–0.18) มีค่าทับกัน
  - ต้องใช้การตัดสินของโมเดล หรือแหล่งค้นที่ดีกว่า
- **Deep ระดับเร็วมีคำค้นแค่ 2 ข้อ** ถ้าแหล่งค้นยังไม่นิ่ง ทางเลือกคือเพิ่ม breadth เป็น 3 ซึ่งเพิ่มค่าใช้จ่ายราวครึ่งหนึ่ง **[อนุมาน]**
