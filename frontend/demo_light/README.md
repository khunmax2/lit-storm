# STORM — คู่มือใช้งานและตั้งค่าระบบ

แอป Streamlit ที่ค้นคว้าหัวข้อจากหลายมุมมอง รวบรวมข้อมูลจากเว็บ และเรียบเรียงเป็นบทความรูปแบบสารานุกรมพร้อมแหล่งอ้างอิง

มีสองเอนจินให้เลือกจากหน้าแรก — **STORM** รันจนจบเองแล้วคืนบทความ ส่วน **Co-STORM** เปิดวงสนทนาที่คุณดู แทรก และกำหนดทิศทางได้ แล้วจึงสั่งเขียนรายงานเมื่อเห็นว่าครอบคลุมพอ ดูรายละเอียดในหัวข้อ **Co-STORM — โต๊ะกลมที่คุณแทรกได้**

โครงการนี้พัฒนาต่อจาก [stanford-oval/storm](https://github.com/stanford-oval/storm) โครงการต้นฉบับหยุดรับ commit เมื่อ 30 กันยายน 2025 (`fb951af`) และไลบรารีบางตัวที่กำหนดเวอร์ชันไว้เริ่มล้าสมัย ขั้นตอนติดตั้งจึงต่างจาก README ต้นฉบับ ดูรายละเอียดในหัวข้อ **สิ่งที่เปลี่ยนจากโครงการต้นฉบับ** ท้ายเอกสาร

> **เอกสารนี้คือคู่มือใช้งาน** ครอบคลุมการติดตั้ง การจัดการสมาชิก Co-STORM และการใช้งานประจำวัน
>
> หากต้องการ **สารบัญค่าตั้งค่าทั้งหมดในที่เดียว** หรือรายละเอียดว่า fork นี้ต่างจาก upstream อย่างไร ดูที่ [README ที่รากโครงการ](../../README.md) (ภาษาอังกฤษ) ส่วนอาการเสียที่พบบ่อยและวิธีแก้ ดูที่ [docs/TROUBLESHOOTING.md](../../docs/TROUBLESHOOTING.md)

ความสามารถหลัก:

1. สร้างบทความจากหัวข้อได้ทั้ง **ภาษาไทยและภาษาอังกฤษ**
2. เลือกได้ระหว่างเอนจิน **STORM** ที่รันจนจบเอง และ **Co-STORM** ที่เปิดวงสนทนาให้แทรกและกำหนดทิศทางได้
3. ติดตามการค้นคว้า เช่น มุมมอง คำถาม และเว็บไซต์ที่ระบบเปิดอ่าน
4. อ่านบทความพร้อมสารบัญและแหล่งอ้างอิง
5. ดาวน์โหลดรายงาน HTML แบบโต้ตอบ รวมบทความ แหล่งอ้างอิงที่กดดูได้ และบทสัมภาษณ์เบื้องหลังไว้ในไฟล์เดียว เปิดได้โดยไม่ต้องใช้เซิร์ฟเวอร์หรืออินเทอร์เน็ต
6. เปิดดูและค้นหาบทความที่เคยสร้าง
7. เลือกแหล่งค้นคว้าจากหน้าตั้งค่า โดยผู้ดูแลระบบทดสอบคีย์ได้ก่อนบันทึก
8. รองรับธีมสว่างและมืด ตามระบบหรือเมนูตั้งค่าของ Streamlit
9. ลบและกู้คืนรายงาน รวมถึงงานที่สร้างไม่สำเร็จ และเปิดดูข้อมูลการค้นคว้าที่บันทึกไว้ได้แม้ยังไม่มีบทความฉบับสมบูรณ์
10. จัดการสมาชิกด้วย dropdown สำหรับบทบาทและสถานะ ป้องกันการลดสิทธิ์บัญชีที่กำลังใช้งาน แสดงข้อมูลที่ยังไม่ได้บันทึก และดูประวัติการจัดการสมาชิก

## การติดตั้งและตั้งค่า

ให้เรียกใช้คำสั่งจากโฟลเดอร์หลักของโครงการ เว้นแต่ขั้นตอนนั้นระบุให้เปลี่ยนโฟลเดอร์

> **เส้นทางคำสั่งต่างกันตามระบบปฏิบัติการ** macOS และ Linux เก็บโปรแกรมของ venv ไว้ที่ `.venv/bin/` ส่วน Windows ใช้ `.venv\Scripts\` คู่มือนี้แสดงทั้งสองแบบในขั้นตอนติดตั้ง หลังจากนั้นจะยกตัวอย่างด้วยรูปแบบ macOS หากใช้ Windows ให้เปลี่ยน `.venv/bin/` เป็น `.venv\Scripts\` ทุกจุด

### 1. สร้างสภาพแวดล้อม Python แยกสำหรับโครงการ

macOS และ Linux:

```bash
python3.14 -m venv .venv
```

Windows (PowerShell) — หากไม่มี `python3.14` บน PATH ให้ใช้ [uv](https://docs.astral.sh/uv/) ซึ่งดาวน์โหลดตัวแปลภาษาให้เองโดยไม่แตะ Python ของระบบ:

```bash
uv venv --python 3.14
```

รองรับ Python 3.11–3.14 คู่มือต้นฉบับแนะนำ conda แต่โครงการนี้ใช้ `venv` ได้ เพราะไม่ต้องพึ่งแพ็กเกจนอก Python ของ conda

venv แต่ละชุดผูกกับตัวแปลภาษาของตนเองผ่าน `pyvenv.cfg` การติดตั้ง Python เวอร์ชันใหม่จึงไม่กระทบ venv ของโครงการอื่นที่สร้างไว้แล้ว

### 2. ติดตั้งไลบรารีและส่วนติดต่อผู้ใช้

macOS และ Linux:

```bash
.venv/bin/pip install -e .
.venv/bin/pip install -r requirements.txt -r frontend/demo_light/requirements.txt watchdog
```

Windows (PowerShell):

```bash
.venv\Scripts\pip install -e .
.venv\Scripts\pip install -r requirements.txt -r frontend\demo_light\requirements.txt watchdog
```

**คำสั่ง `-e .` ข้ามไม่ได้** เพราะขั้นตอนที่ 4 สั่งให้ `cd` เข้าโฟลเดอร์ `frontend/demo_light` ก่อนเปิดแอป ซึ่งเป็นตำแหน่งที่ Python มองไม่เห็น `knowledge_storm` หากข้ามจะพบ `ModuleNotFoundError: No module named 'knowledge_storm'`

`watchdog` จำเป็นสำหรับการโหลดซ้ำอัตโนมัติในขั้นตอนที่ 4 — ดูหัวข้อถัดไป

### 3. ตั้งค่า API key

คัดลอกไฟล์ตัวอย่าง:

macOS และ Linux:

```bash
cp frontend/demo_light/.streamlit/secrets.toml.example \
   frontend/demo_light/.streamlit/secrets.toml
```

Windows (PowerShell):

```powershell
Copy-Item frontend\demo_light\.streamlit\secrets.toml.example frontend\demo_light\.streamlit\secrets.toml
```

> อย่าคัดลอกคำสั่งรูปแบบ macOS มาวางใน PowerShell **เครื่องหมาย `\` ท้ายบรรทัดคือการขึ้นบรรทัดใหม่ของ bash เท่านั้น** PowerShell จะอ่านมันเป็นส่วนหนึ่งของ path ถัดไป กลายเป็น `\frontend\...` ซึ่งชี้ไปรากของไดรฟ์ แล้วแจ้ง `Could not find a part of the path 'D:\frontend\...'`

จากนั้นกรอกค่าในไฟล์ `secrets.toml` ที่ได้มา ทุกค่ามีคำอธิบายกำกับไว้ในไฟล์แล้ว อย่างน้อยที่สุดต้องมีสามค่านี้จึงจะใช้งานได้:

- `GOOGLE_API_KEY` — คีย์ Gemini จาก [ai.google.dev](https://ai.google.dev/gemini-api/docs/api-key)
- `SUPABASE_URL` และ `SUPABASE_ANON_KEY` — หากเว้นทั้งคู่ไว้ หน้าลงชื่อเข้าใช้จะแจ้งว่าตั้งค่าไม่ครบ โดยยังไม่อนุญาตให้เข้าใช้งานส่วนที่ต้องมีบัญชี

และควรเพิ่มอีกหนึ่งค่าที่ไฟล์ตัวอย่างยังไม่ได้ระบุ เพื่อเลี่ยงปัญหาของ alias `-latest` ดูเหตุผลในหัวข้อ **โมเดลและโควตา API**:

```toml
LLM_STRONG_MODEL = "gemini-3.6-flash"
```

ค่าข้อความต้องมีเครื่องหมายคำพูดเสมอ เพราะ TOML ไม่รองรับข้อความที่ไม่มีเครื่องหมายคำพูด ในกรณีนี้ Streamlit อาจแจ้งว่าขาดคีย์แทนการแจ้งข้อผิดพลาดรูปแบบไฟล์

ไฟล์ `secrets.toml` ถูกยกเว้นจาก Git และต้องคงไว้เช่นนั้น ให้เก็บใน Git เฉพาะไฟล์ `.example` ที่ไม่มีคีย์จริง หากไม่มีค่าในไฟล์ ระบบจะอ่านจากตัวแปรสภาพแวดล้อมแทน เหมาะสำหรับการติดตั้งผ่าน container

### 3b. ตั้งค่าบัญชีและสิทธิ์ผู้ใช้

ระบบเก็บข้อมูลบัญชี บทบาท และโควตาค้นคว้ารายเดือนของแต่ละคนใน Supabase

1. สร้างโครงการที่ [supabase.com](https://supabase.com)
2. เปิด **SQL Editor** ใน Supabase วางเนื้อหาทั้งหมดจาก [docs/supabase-schema.sql](../../docs/supabase-schema.sql) แล้วรัน ระบบจะสร้างตารางโปรไฟล์ ประวัติการค้นคว้า ประวัติการจัดการสมาชิก และนโยบายสิทธิ์เข้าถึงข้อมูล โปรไฟล์ผู้ใช้จะถูกสร้างเมื่อเข้าสู่ระบบครั้งแรก หรือเมื่อระบบสร้างบัญชีพร้อมบันทึกที่มาได้
3. หากทดสอบในเครื่อง สามารถปิดการยืนยันอีเมลที่ **Authentication → Providers → Email** ได้ หากเปิดไว้ ผู้สมัครต้องเปิดลิงก์ยืนยันอีเมลก่อนเข้าสู่ระบบ
4. สมัครและเข้าสู่ระบบผ่านแอปก่อน จากนั้นรัน SQL ต่อไปนี้เพื่อกำหนดผู้ดูแลระบบคนแรก โดยเปลี่ยน `you@example.com` เป็นอีเมลของคุณ:

   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```

ระบบมีสองบทบาท:

- `member` — สมาชิก สร้างรายงานและดูรายงานของตนเองได้
- `admin` — ผู้ดูแลระบบ มีความสามารถของสมาชิก และดูประวัติการค้นคว้าของทุกคน รวมถึงจัดการบัญชีผ่านหน้า **สมาชิก** ได้

โควตาค้นคว้าแยกจากบทบาท ค่า `monthly_run_limit` ในโปรไฟล์กำหนดจำนวนครั้งที่แต่ละคนค้นคว้าได้ต่อเดือน ผู้ดูแลปรับได้เป็นรายบัญชี งานที่สร้างไม่สำเร็จยังนับโควตา เพราะอาจใช้ทรัพยากร API ไปแล้ว

แต่ละเซสชัน Streamlit มี Supabase client และสถานะการค้นคว้าของตนเอง เมื่อโหลดหน้าใหม่ ระบบกู้คืนการเข้าสู่ระบบจากคุกกี้ refresh token ตามเวลาที่กำหนด เมื่อออกจากระบบจะล้างข้อมูลหน้าจอและตัวประมวลผลของบัญชีนั้นก่อนให้บัญชีอื่นเข้าสู่ระบบ

### 3c. เปิดใช้ระบบจัดการสมาชิกที่อัปเดต

**สำหรับโครงการที่ตั้งค่า Supabase ไว้แล้ว:** ให้นำเนื้อหาทั้งหมดของ [docs/supabase-schema.sql](../../docs/supabase-schema.sql) ไปรันอีกครั้งใน **SQL Editor** เพื่อเปิดใช้การบันทึกสมาชิกทั้งชุด การป้องกันลดสิทธิ์หรือระงับบัญชีตนเอง การตรวจสถานะบัญชี และประวัติการจัดการสมาชิก

คำสั่งนี้คงข้อมูลโปรไฟล์และประวัติการค้นคว้าเดิมไว้ บัญชีเก่าที่ไม่เคยบันทึกที่มาจะระบุว่าไม่ทราบที่มา โดยไม่เดาว่าใครเป็นผู้สร้าง

หากต้องการให้ admin เพิ่มสมาชิกได้ ต้องตั้งค่า `SUPABASE_SECRET_KEY` ซึ่งเป็นคีย์ฝั่งเซิร์ฟเวอร์เท่านั้น ดูที่มาของคีย์และข้อห้ามในการใช้งานได้จากคำอธิบายใน [.streamlit/secrets.toml.example](.streamlit/secrets.toml.example)

หากยังไม่ได้ตั้งค่า ฟอร์มเพิ่มสมาชิกจะยังใช้งานไม่ได้ ส่วนการแก้ไขสมาชิกเดิมใช้ token ของ admin ที่เข้าสู่ระบบ จึงไม่ต้องใช้คีย์พิเศษนี้ แต่ต้องอัปเดตฐานข้อมูลก่อน

#### เพิ่มสมาชิกโดยผู้ดูแลระบบ

1. เข้าสู่ระบบด้วยบัญชี admin แล้วเปิดหน้า **สมาชิก**
2. เลือก **เพิ่มสมาชิก**
3. กรอกชื่อ อีเมล และรหัสผ่าน เช่นเดียวกับการสมัครสมาชิก
4. ตรวจสอบว่าอีเมลเป็นของสมาชิกที่จะเพิ่ม แล้วเลือกช่องยืนยัน
5. กด **เพิ่มสมาชิก**

บัญชีใหม่จะมีบทบาท `member` และสถานะ **ใช้งานได้** สามารถเข้าสู่ระบบด้วยรหัสผ่านที่กำหนดได้ทันที ระบบไม่ส่งอีเมลต้อนรับหรืออีเมลยืนยัน การสร้างสมาชิกไม่เปลี่ยนบัญชี admin ที่กำลังเข้าสู่ระบบอยู่

หากบันทึกโปรไฟล์หรือประวัติการสร้างบัญชีไม่สำเร็จ ระบบจะลบบัญชี Auth ที่เพิ่งสร้างเพื่อย้อนกลับการทำงาน หากย้อนกลับหรือบันทึกประวัติข้อผิดพลาดไม่ได้ จะแจ้งให้ตรวจสอบและแก้ไขบัญชีที่ค้างใน Supabase ก่อนลองใหม่

#### แก้ไขบทบาท สถานะ และโควตา

บัญชีที่เข้าสู่ระบบอยู่มีป้าย **บัญชีที่คุณกำลังใช้งาน** และล็อกช่องบทบาทกับสถานะไว้ ฐานข้อมูลป้องกันการลดสิทธิ์หรือระงับบัญชีตนเองด้วย แอปไม่มีฟังก์ชันลบบัญชีสมาชิก และผู้ใช้ที่เข้าสู่ระบบไม่มีสิทธิ์ `DELETE` โปรไฟล์

หากต้องการหยุดการใช้งานของบัญชีอื่น ให้เลือกสถานะ **ระงับการใช้งาน** หากต้องการคืนสิทธิ์ ให้เปลี่ยนกลับเป็น **ใช้งานได้** รายงานและประวัติการค้นคว้าของบัญชีนั้นจะยังอยู่

การบันทึกหลายบัญชีจะสำเร็จพร้อมกันทั้งชุด พร้อมบันทึกค่าเดิมและค่าใหม่ หากผู้ดูแลคนอื่นเปลี่ยนข้อมูลไปแล้ว ระบบจะปฏิเสธการบันทึกข้อมูลชุดเก่าเพื่อป้องกันการเขียนทับ

- **บันทึกการแก้ไข**: สีจางและกดไม่ได้เมื่อไม่มีการแก้ไข เปิดใช้งานและสีเข้มขึ้นเมื่อมีข้อมูลรอบันทึก
- **ยกเลิกการแก้ไข**: ทิ้งการแก้ไขที่ยังไม่บันทึก แล้วโหลดค่าล่าสุดจากฐานข้อมูล

ระบบตรวจสิทธิ์ใหม่เมื่อผู้ใช้โต้ตอบกับหน้าแอปครั้งถัดไป การเปลี่ยนบทบาทหรือระงับบัญชีจึงมีผลในการใช้งานครั้งถัดไป

#### ตรวจสอบที่มาของบัญชีและประวัติการแก้ไข

เปิดแท็บ **ประวัติการจัดการสมาชิก** เพื่อดูผู้ดำเนินการ บัญชีที่เกี่ยวข้อง ช่องทาง เวลา และผลการดำเนินการ ข้อมูลอยู่ในตาราง `member_audit_log` ผู้ดูแลอ่านได้ แต่สมาชิกทั่วไปเพิ่ม แก้ไข หรือลบประวัตินี้ไม่ได้ ระบบไม่เก็บรหัสผ่านหรือ API key ในประวัติ

ที่มาของบัญชีแบ่งเป็น:

- `self_signup` — สมัครผ่านแอปด้วยตนเอง โดยระบบตั้งค่าคีย์ฝั่งเซิร์ฟเวอร์ไว้แล้ว
- `admin_create` — ผู้ดูแลสร้างให้ พร้อมระบุผู้ดูแลที่ยืนยันตัวตนแล้ว
- `first_sign_in` — สร้างโปรไฟล์เมื่อเข้าสู่ระบบครั้งแรก แต่ไม่ทราบช่องทางที่สร้างบัญชี Auth เช่น กรณีไม่มีคีย์ฝั่งเซิร์ฟเวอร์
- `legacy_unknown` — บัญชีเดิมที่ไม่มีข้อมูลที่มา

ประวัตินี้ไม่ครอบคลุมการเปลี่ยนข้อมูลโดยตรงจาก Supabase dashboard นอกแอป

การทดสอบฐานข้อมูลไม่เชื่อมต่อ Supabase แต่**สร้าง cluster PostgreSQL ชั่วคราวขึ้นมาเองด้วย `initdb`** แล้วติดต่อผ่าน Unix socket โดยปิดการรับเชื่อมต่อ TCP ให้ติดตั้ง PostgreSQL หรือกำหนด `STORM_POSTGRES_BIN` เป็นโฟลเดอร์ `bin` ของ PostgreSQL หากไม่พบไบนารี โปรแกรมทดสอบจะข้ามส่วนนี้ ก่อนตรวจสิทธิ์บัญชีจริง ให้ปิดโหมดบัญชีจำลองของแอป

เพราะเทสต์ปั้น cluster ของตัวเอง การเปิด PostgreSQL ไว้ใน Docker จึงไม่ช่วยให้เทสต์ชุดนี้รันได้ — เทสต์ไม่ได้ต่อเข้า server ที่มีอยู่

cluster ฟังที่ `127.0.0.1` บนพอร์ตว่างที่หาให้ตอนเริ่ม ใช้ scram-sha-256 กับรหัสผ่านที่สุ่มใหม่ทุกครั้ง ไม่ได้ใช้ Unix socket เพราะ Windows ไม่มี และการมีเส้นทางเดียวทำให้ทั้งสองแพลตฟอร์มรันเทสต์ชุดเดียวกัน

> **เหลือเทสต์ตัวเดียวที่ยังรันบน Windows ไม่ได้** [tests/test_article_store.py](../../tests/test_article_store.py) มีการตรวจการหนีออกจากโฟลเดอร์ด้วย symlink ซึ่งต้องมีสิทธิ์สร้าง symlink จะได้ `WinError 1314` หากไม่ได้เปิด Developer Mode คาดว่าจะเห็น 41 ผ่าน 1 error

### 4. เปิดแอป

macOS และ Linux:

```bash
cd frontend/demo_light
../../.venv/bin/streamlit run storm.py --server.runOnSave true
```

Windows (PowerShell):

```bash
.venv\Scripts\streamlit run frontend\demo_light\storm.py --server.runOnSave true
```

จากนั้นเปิด [http://localhost:8501](http://localhost:8501)

ให้เรียก `streamlit` ผ่านเส้นทางของ `.venv` ตามตัวอย่าง หรือเปิดใช้งาน venv ก่อนด้วย `source .venv/bin/activate` บน macOS และ Linux หรือ `.venv\Scripts\activate` บน Windows หากใช้ `streamlit run` โดยตรง ระบบจะค้นหาโปรแกรมจาก PATH ของเครื่อง ซึ่งอาจไม่มีโปรแกรมนี้หรือเป็นคนละเวอร์ชัน

#### เรื่อง `--server.runOnSave` ที่ต้องรู้ก่อนพัฒนา

หากไม่ใส่ตัวเลือกนี้ Streamlit จะไม่โหลดซ้ำเมื่อคุณแก้ **โมดูลที่ถูก import** เช่น `demo_util.py` หรือ `costorm.py` จะโหลดซ้ำเฉพาะสคริปต์หลักเท่านั้น ผลคือแก้โค้ดแล้วหน้าจอไม่เปลี่ยน ดูเหมือนการแก้ไขไม่มีผล ทั้งที่ต้องรีสตาร์ตเซิร์ฟเวอร์ ต้องติดตั้ง `watchdog` ด้วย ไม่อย่างนั้นการเฝ้าไฟล์จะไม่ทำงาน

> **ตัวเลือกนี้มีราคาที่ต้องจ่าย** การบันทึกไฟล์ระหว่างที่ Co-STORM กำลังเริ่มต้นวงสนทนาจะรีสตาร์ตสคริปต์และ**ทำให้งานที่กำลังรันหายไปทั้งหมด** ซึ่งอาจเป็นงานสิบกว่านาที อย่าแก้ไฟล์ระหว่างรอวงสนทนาเริ่ม

รายงานเก็บใน `frontend/demo_light/DEMO_WORKING_DIR/<user-id>/` ซึ่งถูกยกเว้นจาก Git ผู้ใช้ต้องเข้าสู่ระบบก่อนอ่านหรือเขียน workspace ระบบไม่ใช้โฟลเดอร์รวมเดิมเป็นพื้นที่สำหรับผู้ที่ยังไม่เข้าสู่ระบบ

ผู้ดูแลเห็นคลังบทความของตนเอง ส่วนหน้า **สมาชิก** แสดงข้อมูลประวัติการค้นคว้าของทุกบัญชีได้ตามสิทธิ์ฐานข้อมูล การตั้งค่าโมเดลและแหล่งค้นคว้ายังใช้ร่วมกันทั้งระบบ

### การจัดการรายงาน

เปิดเมนู **⋮** บนการ์ดรายงานเพื่อลบ รายงานจะย้ายไปยังโฟลเดอร์ `.trash/` ของบัญชีที่เข้าสู่ระบบ สามารถกู้คืนจากส่วนรายงานที่ลบแล้วได้ แม้โหลดแอปใหม่ การกู้คืนจะไม่เขียนทับรายงานชื่อเดียวกันที่มีอยู่

ประวัติการค้นคว้าในฐานข้อมูลยังคงอยู่ การลบรายงานจึงไม่คืนโควตาที่ใช้ไป

ปุ่ม **ดูรายละเอียด** เปิดโครงร่าง บันทึกบทสนทนา และข้อมูลแหล่งอ้างอิงที่บันทึกไว้ของงานที่สร้างไม่สำเร็จ หากไฟล์ว่างหรือเสียหายจะแจ้งว่าไม่มีข้อมูล โดยไม่แสดงไฟล์ตั้งค่าผู้ให้บริการ

ขณะนี้ยังไม่มีปุ่มรันซ้ำหรือทำต่อจากรายงานเดิมในคลัง ปุ่มเริ่มใหม่บนหน้าสร้างไม่สำเร็จจะกลับไปยังแบบฟอร์มหัวข้อ ไม่ได้ทำต่อจากงานที่บันทึกไว้

#### รายงาน HTML แบบโต้ตอบ

บทความที่เห็นบนหน้าจอเป็นเพียงส่วนที่มองเห็นได้ของงานหนึ่งชิ้น เบื้องหลังยังมีแหล่งข้อมูลที่ค้นพบ คำค้นที่พาไปเจอแต่ละแหล่ง และบทสัมภาษณ์ที่แต่ละมุมมองใช้ การดาวน์โหลดเป็น `.md` จะทิ้งข้อมูลเหล่านั้นทั้งหมด เหลือเพียงตัวเลขในวงเล็บที่ไม่ชี้ไปไหน

รายงาน HTML รวมทุกอย่างไว้ในไฟล์เดียว ทั้งบทความพร้อมการอ้างอิงที่กดดูได้ หลักฐานเบื้องหลังการอ้างอิงนั้น และบทสัมภาษณ์ที่ผลิตมันขึ้นมา ทุกอย่างฝังอยู่ในไฟล์ จึงเปิดได้ทุกที่โดยไม่ต้องใช้เซิร์ฟเวอร์ ขั้นตอน build หรือแม้แต่อินเทอร์เน็ต ส่งให้อาจารย์ที่ปรึกษาทางอีเมลหรือวางไว้ในไดรฟ์ที่ใช้ร่วมกันแล้วยังทำงานได้เหมือนเดิม

ทดสอบการจัดเก็บรายงาน หน้าคลัง การแยกบัญชี และการจัดการสมาชิก โดยเรียกคำสั่งนี้จากโฟลเดอร์หลักของโครงการ:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

บน Windows ใช้ `.venv\Scripts\python -m unittest discover -s tests -v` และดูข้อจำกัดของเทสต์ฐานข้อมูลในขั้นตอนที่ 3c

### พัฒนาหน้าจอด้วยบัญชีจำลอง

Streamlit เก็บเซสชันในหน่วยความจำ เมื่อสคริปต์เริ่มทำงานใหม่อาจต้องเข้าสู่ระบบอีกครั้ง หากต้องการพัฒนาหน้าจอที่อยู่หลังระบบเข้าสู่ระบบ ให้เปิดโหมดบัญชีจำลอง

macOS และ Linux — จากโฟลเดอร์ `frontend/demo_light`:

```bash
STORM_DEV_USER=1 ../../.venv/bin/streamlit run storm.py --server.runOnSave true
```

Windows (PowerShell) — จากโฟลเดอร์หลักของโครงการ PowerShell ไม่รองรับการนำหน้าคำสั่งด้วยตัวแปรสภาพแวดล้อม จึงต้องตั้งค่าแยกบรรทัด:

```bash
$env:STORM_DEV_USER = "1"
.venv\Scripts\streamlit run frontend\demo_light\storm.py --server.runOnSave true
```

ค่าที่ตั้งด้วย `$env:` มีผลเฉพาะหน้าต่าง PowerShell นั้น ปิดแล้วหายไป

> **ตั้งค่านี้ในสภาพแวดล้อมเท่านั้น อย่าใส่ลง `secrets.toml`** ฟังก์ชัน `setting()` ใน [auth.py](auth.py) อ่าน `secrets.toml` **ก่อน** สภาพแวดล้อม หากใส่ไว้ในไฟล์ จะไม่สามารถปิดโหมดจำลองด้วยตัวแปรสภาพแวดล้อมได้อีก และทุกพอร์ตที่เปิดจากเครื่องนี้จะข้ามการเข้าสู่ระบบทั้งหมด

บัญชีจำลองมีบทบาท admin โดยค่าเริ่มต้น จึงเปิดหน้าสมาชิกได้ หากต้องการดูหน้าจอแบบสมาชิก ให้ตั้ง `STORM_DEV_ROLE=member` แถบด้านบนจะแจ้งชัดเจนว่ากำลังใช้โหมดนี้และปิดแถบไม่ได้ ปุ่ม **ออกจากระบบ** จะหยุดใช้บัญชีจำลองเพื่อให้ดูหน้าเข้าสู่ระบบจริงได้ โหลดหน้าใหม่เพื่อกลับเข้าโหมดจำลอง

โหมดนี้มีข้อจำกัดสามชั้น:

- ไม่ทำงานจนกว่าจะตั้งตัวแปรในสภาพแวดล้อมหรือ `secrets.toml` ซึ่งไม่ควรเก็บลง Git
- ทำงานเฉพาะเมื่อเบราว์เซอร์เรียกผ่าน localhost หรือ loopback ไม่ทำงานผ่าน URL เครือข่ายหรือ proxy ที่ผู้ใช้ทั่วไปเข้าถึง
- ไม่เชื่อมต่อ Supabase โปรไฟล์ รายชื่อสมาชิก และประวัติการค้นคว้าเป็นข้อมูลจำลองในหน่วยความจำ การแก้ไขรายชื่อจึงไม่บันทึกข้อมูลจริง

บัญชีจำลองมีโฟลเดอร์ของตนเองใน `DEMO_WORKING_DIR/` เช่นเดียวกับบัญชีทั่วไป คลังจะเริ่มว่าง สามารถคัดลอกโฟลเดอร์บทความเข้าไปเพื่อทดสอบการ์ดรายงานได้

**การค้นคว้ายังเรียก API จริงและอาจมีค่าใช้จ่าย** โหมดนี้ข้ามเฉพาะการเข้าสู่ระบบ

## โมเดลและโควตา API

ระบบใช้โมเดลสองหน้าที่:

| ขั้นตอน | โมเดล |
| --- | --- |
| ตั้งคำถามและจำลองบทสนทนา | โมเดลเร็ว (**fast**) |
| สร้างโครงร่าง เขียนบทความ และปรับภาษา | โมเดลหลัก (**strong**) |

เลือกผู้ให้บริการได้ผ่านค่าตั้งค่าโดยไม่ต้องแก้โค้ด Gemini เรียกผ่าน `google-genai` SDK ส่วนผู้ให้บริการอื่นเรียกผ่าน LiteLLM

**รายชื่อผู้ให้บริการที่รองรับ ชื่อคีย์ของแต่ละราย และตัวอย่างการตั้งค่าทุกแบบ** อยู่ใน [.streamlit/secrets.toml.example](.streamlit/secrets.toml.example) พร้อมคำอธิบายกำกับในตัวไฟล์ รวมถึงการตั้งโมเดลแต่ละหน้าที่ไว้คนละผู้ให้บริการ และการใช้ `openai-compatible` กับบริการที่รองรับรูปแบบ OpenAI API เช่น z.ai หรือโมเดลที่เปิดบนเครื่องของคุณ

หัวข้อนี้กล่าวเฉพาะสิ่งที่ไฟล์นั้นไม่ได้บอก

ค่าเริ่มต้นในโค้ดคือ `gemini-flash-lite-latest` และ `gemini-flash-latest` ([demo_util.py](demo_util.py)) คู่มือเดิมแนะนำชื่อแบบ `-latest` เนื่องจากเคยพบข้อผิดพลาด 404 และข้อความ *"no longer available to new users"* เมื่อใช้ชื่อรุ่น 2.x ที่ระบุเวอร์ชันตายตัว เช่น `gemini-2.5-flash` กับคีย์ใหม่ แม้ `list_models()` ยังแสดงชื่ออยู่ การเปิดให้ใช้โมเดลขึ้นอยู่กับผู้ให้บริการและบัญชีของคุณ

**แต่คำแนะนำนั้นมีข้อยกเว้นที่ต้องรู้** เมื่อ 2026-09-20 พบว่า `gemini-flash-latest` ชี้ไปที่ `gemini-3.7-flash` ซึ่งคืนข้อผิดพลาด 503 บ่อย และใช้เวลา 30–57 วินาทีกับ prompt คำเดียว ขณะที่รุ่นอื่นตอบใน 1–8 วินาที จึงควรปักหมุดโมเดลหลักออกจาก alias:

```toml
LLM_STRONG_MODEL = "gemini-3.6-flash"
```

ข้อดีของ alias คือไม่ต้องตามแก้เมื่อผู้ให้บริการเลิกรุ่นเก่า ข้อเสียคือรุ่นที่ alias ชี้ไปเปลี่ยนได้โดยไม่บอกล่วงหน้า และประสิทธิภาพอาจแย่ลงข้ามคืน หากจะเลิกปักหมุด ให้วัดเวลาตอบสนองจริงก่อน อย่าเชื่อว่ารุ่นใหม่กว่าต้องเร็วกว่า

มีเพียง Gemini เท่านั้นที่มีชื่อโมเดลเริ่มต้นมาให้ ผู้ให้บริการรายอื่นต้องระบุ `LLM_FAST_MODEL` และ `LLM_STRONG_MODEL` เอง มิฉะนั้นระบบจะแจ้งก่อนเริ่มค้นคว้าแทนการเดาชื่อให้

ระบบเติมส่วนระบุผู้ให้บริการให้เองเสมอ แม้ชื่อโมเดลจะมี `/` อยู่แล้วก็ตาม — `anthropic/claude-sonnet-4` คือชื่อโมเดลบน OpenRouter ไม่ใช่คำสั่งให้เรียก Anthropic โดยตรง

| --- | --- | --- |
| เวลาที่ไม่มีการใช้งาน | 30 นาที | `SESSION_IDLE_MINUTES` |
| เวลาสูงสุดนับจากเข้าสู่ระบบ แม้ยังใช้งานอยู่ | 12 ชั่วโมง | `SESSION_MAX_HOURS` |

คุกกี้เก็บเฉพาะ refresh token ของ Supabase ไม่เก็บรหัสผ่าน ตั้งค่า `SameSite=Strict` และใช้ `Secure` เมื่อให้บริการผ่าน HTTPS

`st.context.cookies` อ่านคุกกี้ที่เบราว์เซอร์ส่งมากับคำขอ จึงอ่านได้ตั้งแต่เริ่มโหลดหน้า ส่วนการเขียนคุกกี้ใช้ `CookieManager` ใน `extra-streamlit-components` เพราะ Streamlit ไม่มี `set_cookie` ไม่ใช้ `get()` ของ component สำหรับกู้คืนเซสชัน เพราะครั้งแรกที่แสดงหน้าจะยังคืนค่า `None`

### ปรับความเร็วให้เหมาะกับโควตา

ค่าตั้งค่าตัวประมวลผลในโครงการออกแบบสำหรับ **API key แบบชำระเงิน**:

```python
max_conv_turn=3, max_perspective=3, num_retries=6   # max_thread_num defaults to 10
```

การค้นคว้าหลายมุมมองพร้อมกันอาจเกินอัตราการเรียก API โดยเฉพาะบัญชีใช้ฟรี คู่มือเดิมอ้างอิงโควตา Gemini ที่ 15 คำขอต่อนาทีต่อโมเดล แต่โควตาจริงขึ้นอยู่กับรุ่นและบัญชี หากพบข้อจำกัด ให้ลดค่าที่ `set_storm_runner()`:

```python
max_conv_turn=2, max_perspective=2, max_thread_num=1
```

ควรคง `num_retries` ไว้ เพราะบัญชีชำระเงินก็อาจได้รับข้อผิดพลาด 429 ผลทดสอบเดิมพบว่าการทำงานพร้อมกันให้ข้อมูลค้นคว้ามากขึ้นและใช้เวลาน้อยลง จึงเพิ่มค่าได้เมื่อโควตารองรับ

หากทุกโมเดลแจ้ง `RateLimitError` พร้อมกัน ให้อ่านรายละเอียดก่อนแก้โค้ด เช่น ข้อความ *"Your prepayment credits are depleted"* หมายถึงเครดิตชำระล่วงหน้าหมด เป็นปัญหายอดเงิน ไม่ใช่ข้อผิดพลาดของโปรแกรม

## แหล่งค้นคว้า

ค่าเริ่มต้นค้นหาผ่าน DuckDuckGo ด้วยแพ็กเกจ `ddgs` จึงไม่ต้องใช้ API key เพิ่ม DuckDuckGo จำกัดอัตราการเรียกค่อนข้างเข้มงวด ระบบจะลองใหม่โดยเพิ่มระยะรอ และข้ามคำค้นที่ยังทำงานไม่สำเร็จแทนการหยุดงานทั้งหมด

เปลี่ยนแหล่งค้นคว้าได้จากหน้า **แหล่งค้นคว้า** โดยไม่ต้องแก้โค้ด ผู้ดูแลระบบเท่านั้นที่เปิดหน้านี้ได้ ตัวเลือกกำหนดไว้ใน [search_sources.py](search_sources.py):

| แหล่ง | คีย์ที่ต้องใช้ |
| --- | --- |
| DuckDuckGo | ไม่ต้องใช้ |
| arXiv | ไม่ต้องใช้ |
| Tavily | `TAVILY_API_KEY` |
| Serper (Google) | `SERPER_API_KEY` |
| Brave Search | `BRAVE_API_KEY` |
| You.com | `YDC_API_KEY` |
| SearXNG | ที่อยู่ instance (`SEARXNG_URL`) — ดู [deploy/searxng](../../deploy/searxng/README.md) |

STORM รับตัวค้นหาได้ครั้งละหนึ่งตัว หน้านี้จึงเป็นการ**เลือก**แหล่ง ไม่ใช่เปิดปิดหลายแหล่งพร้อมกัน ทดสอบคีย์ได้ก่อนบันทึก และคีย์ที่บันทึกแล้วจะแสดงเพียงสี่ตัวท้าย ไม่ถูกส่งกลับไปยังเบราว์เซอร์

`knowledge_storm/rm.py` ยังมี `VectorRM` สำหรับค้นจากเอกสารของคุณเอง แต่ต้องมี collection เตรียมไว้ก่อน จึงยังเลือกจากหน้านี้ไม่ได้

## Co-STORM — โต๊ะกลมที่คุณแทรกได้

แอปนี้มีสองเอนจินอยู่หลังประตูเดียวกัน หน้าแรกจะถามว่าจะใช้ตัวไหน:

| | STORM | Co-STORM |
| --- | --- | --- |
| การทำงาน | รันจนจบเอง แล้วคืนบทความ | คณะผู้เชี่ยวชาญสนทนากันทีละรอบ |
| บทบาทของคุณ | ระบุหัวข้อแล้วรอ | ดู แทรก ถาม และกำหนดทิศทางได้ |
| ได้รายงานเมื่อ | จบกระบวนการ | คุณสั่งเมื่อเห็นว่าครอบคลุมพอแล้ว |

เปิดจากหน้า **โต๊ะกลม** การสนทนาจะไม่เดินหน้าเองจนกว่าจะมีคนสั่ง แต่ละรอบเลือกได้ว่าจะให้วงคุยกันต่อ หรือจะพูดเองแทรกเข้าไป ระบบเสนอคำถามให้เลือกได้ครั้งละสามข้อ และเมื่อพอใจแล้วจึงสั่งเขียนรายงาน ซึ่งจะไปปรากฏในคลังบทความเหมือนบทความจาก STORM

ตัวสลับเอนจินจะถูกซ่อนขณะที่เอนจินใดเอนจินหนึ่งกำลังทำงาน เพราะ ณ จุดนั้นมันไม่ใช่ทางเปลี่ยนใจ แต่เป็นทางทำงานสิบกว่านาทีหาย

### Co-STORM ต้องใช้โมเดล embedding เพิ่ม

ต่างจาก STORM ตรงที่ทุกชิ้นข้อมูลที่เก็บได้จะถูกจัดเข้าแผนผังความคิดด้วย**ความคล้าย** ไม่ใช่ด้วยการถามโมเดลว่าควรอยู่ตรงไหน จึงต้องมีบริการ embedding เพิ่มอีกหนึ่งตัว

สำหรับ Gemini และ OpenAI คีย์เดิมใช้ได้ทั้งสองอย่าง ไม่ต้องตั้งค่าเพิ่ม แต่ผู้ให้บริการที่ขายต่อเฉพาะ chat completions เช่น **OpenRouter และ Groq ไม่มี endpoint สำหรับ embedding เลย** การติดตั้งแบบนั้นต้องระบุบริการแยก:

```toml
ENCODER_PROVIDER = "gemini"
```

หากไม่ตั้งค่า ระบบจะแจ้งข้อผิดพลาดก่อนเริ่มสนทนา ไม่ปล่อยให้ล้มกลางทาง

### หนึ่งวงสนทนาคือการเรียกโมเดล 70–100 ครั้ง

การเริ่มวงสนทนาอาจใช้เวลาถึง 15 นาที ไม่ใช่เพราะค้าง แต่เพราะปริมาณงานจริง โดยประมาณ:

- ~21 ครั้งสำหรับสัมภาษณ์ผู้เชี่ยวชาญ
- 2 ครั้งสำหรับโครงร่าง
- 21–40 ครั้งสำหรับจัดข้อมูลแต่ละชิ้นเข้าแผนผัง
- **หนึ่งครั้งต่อหนึ่งจุดในแผนผัง คูณสอง** — รอบหนึ่งเพื่อร่างรายงาน อีกรอบเพื่อแปลงเป็นบทสนทนาเปิดวง

สองรายการท้ายแปรผันตามขนาดแผนผัง จึงเป็นสาเหตุหลักที่ทำให้ช้า หากต้องการให้เร็วขึ้น ให้ส่งค่าเหล่านี้เพิ่มเข้าไปที่ `RunnerArgument(...)` ใน [costorm.py](costorm.py) ค่าตั้งต้นนิยามไว้ใน `knowledge_storm/collaborative_storm/engine.py`:

| ค่า | ค่าตั้งต้น | ผล |
| --- | --- | --- |
| `warmstart_max_num_experts` | 3 | จำนวนผู้เชี่ยวชาญตอนเริ่มวง |
| `max_search_queries_per_turn` | 3 | จำนวนคำค้นต่อหนึ่งรอบ |
| `max_search_thread` | 5 | จำนวนการค้นหาพร้อมกัน |

โมเดลหลักของ Co-STORM ตั้ง `max_tokens=3000` ไม่ใช่ 1000 ตามงานวิจัยต้นฉบับ เพราะโมเดลที่ใช้การให้เหตุผลจะใช้โควตาส่วนหนึ่งไปกับการคิดก่อนเขียน ที่ 1000 คำตอบกลับมาขาดกลางคันหรือว่างเปล่า

### ข้อจำกัดที่ยังไม่ได้แก้

**วงสนทนาไม่รอดการโหลดหน้าใหม่** เพราะเก็บอยู่ใน session state ของ Streamlit เท่านั้น ยังไม่มีไฟล์บนดิสก์จนกว่าจะสั่งเขียนรายงาน ฝั่งไลบรารีมี `CoStormRunner.to_dict()` อยู่แล้ว แต่ `from_dict()` ยังมี FIXME ค้างไว้ — มันละเลย `lm_config` ที่บันทึกไว้แล้วเรียก `lm_config.init(lm_type=os.getenv("OPENAI_API_TYPE"))` ซึ่งใช้กับ Gemini ไม่ได้ การทำให้วงสนทนาคงอยู่ข้ามการโหลดหน้าจึงต้องเขียนทางกลับเองทั้งหมด

ด้วยเหตุนี้ สถานะของหน้าโต๊ะกลมจึงเก็บด้วยคีย์ขึ้นต้น `costorm_*` แทน `page6_*` เพื่อให้การเดินไปดูคลังบทความแล้วกลับมาไม่ทำให้วงสนทนาหายไป

## ภาษา

การเลือกภาษาแยกเป็นสองส่วน:

- **ภาษาของระบบ** — เลือกจากแถบด้านข้าง ข้อความอยู่ใน [ui_language.py](ui_language.py)
- **ภาษาบทความ** — เลือกในหน้าสร้างบทความ การทำงานอยู่ใน [article_language.py](article_language.py) โดยเพิ่มคำสั่งภาษาให้ DSPy signatures ที่สร้างข้อความสำหรับผู้อ่าน ไม่บังคับภาษาของคำค้น เพราะภาษาคำค้นมีผลต่อแหล่งข้อมูลที่ค้นพบ

หากต้องการเพิ่มภาษา ให้เพิ่มรายการใน `LANGUAGES` ของทั้งสองไฟล์ พร้อมข้อความและคำสั่งภาษาที่เกี่ยวข้อง

## การปรับแต่งระบบ

ระบบสร้าง `STORMWikiRunner` ในฟังก์ชัน `set_storm_runner()` ของ [demo_util.py](demo_util.py) สามารถปรับ `STORMWikiRunnerArguments` โมเดลแต่ละขั้นตอนใน `STORMWikiLMConfigs` หรือตัวค้นหาได้ที่นั่น ดูแนวทางเพิ่มเติมจาก [คู่มือปรับแต่งของโครงการต้นฉบับ](https://github.com/stanford-oval/storm?tab=readme-ov-file#customize-storm)

## สิ่งที่เปลี่ยนจากโครงการต้นฉบับ

การแก้ไขที่บันทึกไว้ในโครงการนี้:

- เปลี่ยน `duckduckgo_search` เป็น `ddgs` หลังแพ็กเกจเปลี่ยนชื่อ แพ็กเกจเดิมยัง import ได้และตอบ HTTP 200 แต่ไม่ส่งผลค้นหากลับมา ทำให้ดูเหมือนระบบทำงานทั้งที่ไม่มีข้อมูลค้นคว้า
- แก้การรายงานความคืบหน้าจาก worker threads ซึ่ง Streamlit รุ่นใหม่อาจแจ้งข้อผิดพลาดเมื่อ thread ไม่มี script context
- แก้ลิงก์สารบัญที่ไม่ตรงกับหัวข้อ โดยเฉพาะหัวข้อที่ไม่มีอักษรละติน และรหัสหัวข้อแบบ hash ของ Streamlit ที่ไม่ตรงกับชื่อหัวข้อ
- ปรับไลบรารี เนื่องจาก `streamlit==1.31.1` ใช้ร่วมกับ NumPy 2 ไม่ได้
- กำหนดพื้นให้ `sentence-transformers>=3` เดิมเขียนไว้โดยไม่ระบุเวอร์ชัน ตัวแก้ปัญหาเวอร์ชันจึงเลือก 2.2.2 ซึ่งเรียก `cached_download` ที่ `huggingface_hub` ถอดออกไปตั้งแต่ 0.26 ผลคือ `ImportError` ตั้งแต่ตอน import และเพราะ `knowledge_storm/storm_wiki/modules/__init__.py` ดึง `storm_dataclass` เข้ามา แอปจึงเปิดไม่ขึ้นเลย ปัญหานี้เกิดกับการติดตั้งใหม่ทุกระบบปฏิบัติการ ไม่ใช่เฉพาะ Windows

การแก้ไขในไลบรารี `knowledge_storm` ที่นำมาไว้ในโครงการนี้ ซึ่งโครงการต้นฉบับยังไม่มี:

- `lm.py` — เขียน `GoogleModel` ใหม่ ย้ายจาก SDK เดิม `google-generativeai` ที่เลิกพัฒนาแล้วมาเป็น `google-genai`
- `encoder.py` — เพิ่ม Gemini เดิมรองรับเฉพาะ OpenAI และ Azure ทำให้การติดตั้งที่ใช้ Gemini สร้างแผนผังความคิดของ Co-STORM ไม่ได้เลย
- `logging_wrapper.py` — `log_pipeline_stage` กลืนข้อผิดพลาดทุกชนิดโดยไม่ส่งต่อ ทำให้ `generate_report` คืนค่า `None` โดยไม่มีที่ใดแสดงสาเหตุ
- `dataclass.py` — เรียก `replace("[-1]", "")` ซ้ำสองครั้งโดยทิ้งผลทั้งคู่ เครื่องหมาย `[-1]` ที่แปลว่าหาแหล่งอ้างอิงไม่เจอจึงหลุดไปถึงผู้อ่าน
- `rm.py` — แก้สี่จุดใน `TavilySearchRM` และ `DuckDuckGoSearchRM` รวมถึง `giveup_hdlr` ที่อ่าน `err.message` ซึ่งมีเฉพาะใน SDK ของ Mistral ทำให้ข้อจำกัดอัตราของ DuckDuckGo กลายเป็น `AttributeError` ที่กลบสาเหตุจริง

รายละเอียดทั้งหมดของแต่ละจุด พร้อมตัวเลขการเปรียบเทียบกับ upstream อยู่ใน [README ที่รากโครงการ](../../README.md#changes-to-the-upstream-library)

ความสามารถที่เพิ่ม:

- ปรับหน้าจอใหม่ รองรับธีมมืด ภาษาระบบไทย และบทความภาษาไทย
- แสดงความยาวเป็นจำนวนตัวอักษรสำหรับภาษาที่ไม่ได้เว้นวรรคระหว่างคำ เพราะการนับจากช่องว่างอาจนับทั้งประโยคเป็นเพียงหนึ่งคำ
- เพิ่มเอนจิน Co-STORM เป็นทางเลือกคู่กับ STORM พร้อมหน้าโต๊ะกลมสำหรับแทรกและกำหนดทิศทางการสนทนา
- เพิ่มรายงาน HTML แบบโต้ตอบที่รวมบทความ แหล่งอ้างอิง และบทสัมภาษณ์ไว้ในไฟล์เดียวแบบเปิดได้ทุกที่
- เพิ่มหน้าเลือกแหล่งค้นคว้าสำหรับผู้ดูแลระบบ พร้อมการทดสอบคีย์ก่อนบันทึก แทนการแก้โค้ด
- เพิ่มระบบบัญชีและจัดการสมาชิกบน Supabase พร้อมโควตาค้นคว้ารายเดือนและประวัติการจัดการ

คู่มือเดิมระบุว่าทดสอบกับ Streamlit 1.60 บน Python 3.14
